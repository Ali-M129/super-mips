# یادداشت بازبینی نهایی SuperMIPS

## اصلاحات اعمال‌شده

1. **حل صریح تصادم نوشتن در Write Back**
   - `wb_collision` اکنون از write-intentهای خام محاسبه می‌شود.
   - هنگام مقصد یکسان، فقط `wb_we1` معتبر می‌ماند و `wb_we0` صفر می‌شود.
   - lane1 دستور جوان‌تر است، بنابراین مقدار آن از نظر ترتیب برنامه مقدار نهایی صحیح است.

2. **لایهٔ دفاعی مستقل در Register File**
   - حتی اگر ماژولی خارج از مسیر معمول هر دو پورت را با مقصد یکسان فعال کند، فقط پورت lane1 نوشتن معتبر دارد.
   - همین اولویت در bypass همان چرخه نیز اعمال می‌شود.

3. **تمیزکاری تصمیم BEQ**
   - Decoder برای BEQ عمل `ALU_SUB` را انتخاب می‌کند.
   - تصمیم branch-taken اکنون از خروجی `zero` همان ALU استفاده می‌کند و مقایسهٔ موازی اضافی حذف شده است.

4. **شفاف‌سازی سیاست کنترل slot1**
   - منطق dummy مربوط به metadata بلااستفاده حذف شد.
   - با کامنت توضیح داده شده که control در slot1 عمداً می‌تواند کنار slot0 امن صادر شود.

## مواردی که عمداً تغییر نکردند

- کنترل بودن slot0 همچنان slot1 را متوقف می‌کند. این سیاست با Always-Not-Taken ناسازگار نیست؛ پردازنده در چرخه‌های بعد مسیر ترتیبی را ادامه می‌دهد. صدور هم‌زمان دستور fall-through پشت branch در slot0 با منطق فعلی امن نیست، چون دستور جوان‌تر هم‌زمان با branch به E/M می‌رسد و برای store یا writeback به squash انتخابی lane1 نیاز خواهد داشت.
- `advance_count_illegal` حذف نشد؛ هرچند Issue Unit مقدار 3 تولید نمی‌کند، این یک کنترل دفاعی معتبر در مرز رابط Front-end است.
- `memory_alignment_error` رفتار معماری ایجاد نمی‌کند، چون پروژه trap/exception برای آدرس ناهم‌تراز تعریف نکرده است؛ آدرس‌های برنامه باید مضرب چهار باشند.
- تقسیم بر صفر برابر صفر و MUL/DIV ترکیبی، تصمیم‌های طراحی مستندشده هستند و رفتار موجود حفظ شده است.
- مقادیر `supermips_defs.vh` با کد پایهٔ تمرین هفتم تطبیق داده شدند و یکسان‌اند.
